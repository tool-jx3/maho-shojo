# 魔女傳說參考資料庫 設計規格

- 日期：2026-09-08
- 狀態：已核准（使用者確認，不含「取材建議」一節）
- 產出位置：`reference/`

## 1. 目的

蒐集歷史上的魔女／女巫傳說，**以該傳說發源語言的維基百科條目為主要來源**，保存原文並完整翻譯成繁體中文，依「地區／語系／時代」三軸整理，供 Mahō Shōjo 專案作為背景資料查閱。

本資料庫**不併入 Astro 網站**，是 repo 根目錄下的獨立資料夾。

## 2. 範圍

- 收錄類型：民俗／神話中的魔女形象 + 真實的女巫審判事件 + 相關文獻與法制。
- 首批規模：35 條。
- 原文粒度：導言與關鍵章節**逐段原文＋逐段繁中對譯**；其餘章節以繁中摘要涵蓋，並附原文連結。
- **不含**「用於 Mahō Shōjo 的取材建議」一節（使用者明確排除）。

## 5. 取得原文的方法

以維基百科 API 取純文字，避免 wikitext 標記混入引文：

```
https://<lang>.wikipedia.org/w/api.php?action=query&prop=extracts&explaintext=1&redirects=1&format=json&titles=<TITLE>
```

需要原始標記（表格、模板參數）時再取 `?action=raw`。

## 6. 翻譯與寫作規範

沿用專案的 Immutable Laws：

- **Law 6**：一律繁體中文（zh-TW），不得出現簡體字或中國大陸用語。
- **Law 8**：全形標點（：，。、；「」『』（）……），數字與拉丁文字用半形；省略號用 `……`。
- **Law 9**：罕用字、雙關、文化負載詞若影響語意或語氣，先向使用者提出 2～3 個候選再定案。
- 原文引文**逐字保留**，不修正原文的拼寫與標點。
- 譯文求信達，不過度在地化；避免以中文典故成語替換西文概念（見既有專案慣例）。
- 專有名詞**不寫入 `glossary.json`**（該檔為遊戲規則術語庫），統一收錄於 `reference/name-glossary.md`。

## 7. 來源政策

- 優先使用**傳說發源語言**的維基版本（俄語條目用 `ru`、巴斯克傳說用 `eu`／`es`、日本用 `ja`……）。
- 發源語言無條目或內容過於單薄時，退用最近的學術通行語版本（`es`／`pt`／`en`／`fr`／`de`），並於 frontmatter 的 `fallback_reason` 說明。
- 每條目必須記錄語言版本、URL、擷取日期。
- 維基百科內容為 CC BY-SA 4.0，`README.md` 統一標註授權與姓名標示方式。

## 附錄 B：第三批（2026-09-09）東亞條目

### 起因

使用者問「為什麼東亞語系的項目很少」。查核結果：61 條裡東亞只有 4 條（6.6%）。三個原因，都有數據：

1. **整個選錄框架是歐洲的。** 獵巫是歐洲特有的宗教—法律現象；東亞的對應概念散在呪術、陰陽道、憑き物、巫覡、蠱等完全不同的分類名底下，不會出現在任何「巫術」分類樹裡。
2. **掃描種子沒有任何 CJK 分類。** 第二次收緊掃描時把 `ja:Category:魔女` 拿掉（它一直撈進動畫），zh 與 ko 從頭到尾沒放進去。待辦清單結構上就不可能浮出東亞條目（掃描前 ja 276、zh 0、ko 0）。
3. **各語言維基的分類結構本來就不同。** 實查：`zh:Category:巫術` 是空的、`ko:분류:무속` 只有 3 條，而 `ja:Category:呪術` 有 95 條。
4. **來源本身也真的薄。** 實測純文字字數：歐洲優先候選 8,879—112,801 字，東亞優先候選 678—8,282 字。日文最大的〈安珍・清姫伝説〉10,973 字，約為德語〈Hexenverfolgung〉88,134 字的八分之一。這不是選錄能解決的。

### 對應的修正

- `find_reference_candidates.py` 加入 8 個 CJK 種子（`ja:呪術`／`陰陽道`／`シャーマニズム`／`日本の妖怪`、`zh:中國民間信仰`／`薩滿教`、`ko:무속`／`샤머니즘`），並補上日文虛構作品子分類的排除規則。掃描後 ja 597、zh 257、ko 73。
- `BACKLOG.md` 的優先候選改用實測純文字字數，並標出「篇幅偏薄」（低於 4000 字）者；各主題清單的數字改稱「原始碼位元組」並註明跨語系不可比。
- 人工挑選的優先候選即使不在機器掃描結果內也照樣列出，不再被靜默丟棄。

### 工具修正（這一輪的主要教訓）

**檢查器分不出「日文原文」與「簡體中文」**——日語新字體與簡體字形相同，而 `check_reference.py` 原本只靠「這一行有沒有假名」判斷。這個缺陷讓四個 agent 為了通過檢查而扭曲內容：合併章節標題、刪掉說明文字、在標題塞假名讀音、把來源網址改成百分比編碼。工具反過來塑造了內容，方向是錯的。

修正後改用 frontmatter 的 `language` 判斷，對 `ja`／`zh`／`ko` 條目豁免：章節標題行、專有名詞對照表的前兩欄（原文、羅馬轉寫）、`〈〉《》「」『』` 內的原文詞、以及 URL。生成的索引檔（`INDEX.md`、`indexes/`、`name-glossary.md`）同樣適用。

其他修正：

- `check_coverage.py` 取中文章節名時未帶 `variant=zh-tw`，拿到簡體章節名而與正體條目永遠對不上（既有的 `wugu-zhi-huo` 因此被誤判 67%，實為 100%）。另補上 `注釋`、`같이 보기` 等章節名。
- `fetch_wiki.py` 的 `retrieved` 日期寫死，改為動態取得。
- `check_coverage.py` 支援 `wiki_tertiary`（聞得大君與狐狸精都並用了三個來源條目）。

### 新增的擷取陷阱紀錄

已寫入 `reference/README.md` 的「擷取的已知陷阱」一節：引文模板（`{{quotation}}`／`{{Zitat}}`／`{{Cytat}}`）的內容不會出現在純文字擷取結果中，最關鍵的原著引文往往整段消失，須以 `action=raw` 補回；`prop=info` 的 `length` 是 wikitext 位元組數且跨語系不可比；中文條目要指定 `zh-tw` 變體；標題可能是消歧義頁或重導向。

### 交叉引用的處理
