# 測驗題庫

`/quiz` 頁（`src/pages/quiz.astro`）用的題庫與計分。

## 要改題目、選項、權重

只要編輯 **`src/data/quiz-questions.json`**，不必動 `.astro`：

```json
{"t":"越強越好，我要贏過他","w":{"挑戰":2}}
```

- `pact`：4 題，`w` 的鍵是盟約名稱
- `attribute`：屬性題，`w` 的鍵是五項屬性
- `friendship`：前兩題不需要 `w`（依序對應 `breadth` 額外羈絆數與 `focus` 標籤對象），
  後兩題的 `w` 是友情扮演書名稱的陣列

改完跑：

```bash
npm run quiz-report
```

會檢查名稱有沒有打錯，並印出五項屬性的權重合計與三段的出線率分佈。
`npm test` 也會跑同一套檢查，所以打錯字會讓測試失敗，不會靜默失效。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `scoring.mjs` | 計分邏輯。**唯一的來源**：頁面在建置時把它去掉 `export` 後內嵌，測試直接 import 同一個檔案 |
| `lib.mjs` | 題庫檢查與出線率統計 |
| `lib.test.mjs` | `npm test` 會跑的檢查 |
| `report.mjs` | `npm run quiz-report` |

## 需要知道的兩件事

**校準成本**　扮演書配對要先算出各本在「所有可能作答」下的平均與標準差，
成本是各題選項數的乘積。目前 9 題（4^9 ≈ 26 萬）約 0.18 秒，趁瀏覽器閒置時算好。
超過 `CALIBRATION_LIMIT`（50 萬）會自動改用固定種子的抽樣，所以加題不會讓頁面卡住
（12 題時 4^12 ≈ 1678 萬，抽樣後仍是 0.37 秒）。

**題數不影響平衡**　實測過 5～10 題，出線率落差都在 2.2–3.0 倍之間震盪，
加題沒有幫助。真正有效的是五項屬性的權重是否均衡，以及計分方式
（改用 z 分數校準後從 2.6 倍收斂到 1.45 倍）。
